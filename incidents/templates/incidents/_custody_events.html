{% load i18n ui accounts_tags %} {% comment %} The chain of custody of one evidence item (A.5.28) : one row per handling act, in the order the acts happened. Rendered inside the evidence file and swapped into `#custody-events` by `incidents:custody-events` after an append, so it must stand on its own. Context : `evidence`, `custody_events` (ordered by `occurred_at`, then by the recording time to break a tie deterministically) and `custody_form`, which is absent for a reader without `incidents.evidence.update`. **Append-only, and the markup says so.** No edit control and no delete control : a ledger that can be rewritten is not a ledger, the model refuses both, and the URLconf offers neither route. A mistake is corrected by appending a further row whose notes state what the earlier one got wrong ; the earlier row is never touched. The ledger reads oldest first, unlike the chronology : this is a chain, and a chain is read from the acquisition forward. `occurred_at` and `recorded_at` are both rendered whenever they differ, because the gap between the act and its recording is itself information the auditor is entitled to see. {% endcomment %} {% has_perm "incidents.evidence.update" as can_update_evidence %} {% if custody_form and can_update_evidence %} {% comment %} Only the acts Cairn cannot observe are offered here : collection, sealing, analysis, release and destruction are appended by the item's own transitions, and integrity verification is produced by the measurement, never asserted. {% endcomment %}
